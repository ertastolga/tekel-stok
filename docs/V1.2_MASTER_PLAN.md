## 0. Context

V1.1 (Sales-First touch POS) is the stable baseline. V1.2 turns it into a polished,
configurable, commercially credible shop product **without rewriting it** and without
weakening any V1.1 accounting / inventory / barcode / backup / sales invariant.

* **KASA** — scan → basket → NAKİT/KART → next customer. Touch-first, non-modal,
  never PIN-gated, never slowed by management features.
* **STOK / YÖNETİM** — catalogue, categories, import, purchasing, prices, analytics,
  settings, backup, diagnostics. May be dense; sensitive actions PIN-gated.

Execution model: approved once; then every milestone runs autonomously
(implement → tests → full default suite → fix without weakening → commit → log → continue).

Architecture facts that shape V1.2 (all verified in code):
* Already present and reusable without migration: `price_history` (`MANUAL|BULK`),
  `sale_items.is_estimated_cost`, `products.last_purchase_cost/last_avg_cost/last_purchase_at_utc`,
  hierarchical `categories(parent_id, name_norm, active)` with per-parent normalized uniqueness,
  multi-draft `cart_drafts(label)`, brands/families/tags, `default_supplier_id`, `vat_rate`,
  `audit_log.details_json`, auto-backup (`otomatik_`, interval 120 min, keep 10).
* SQLite CHECK lists cannot be altered → V1.2 uses **only additive** `ADD COLUMN` /
  `CREATE TABLE` / `CREATE INDEX` (all planned steps validated on SQLite 3.45.1).
* `transaction()` nests without savepoints → bulk operations validate first, then write with
  no try/except inside the transaction.
* Settings live in the DB; new keys need no migration (`seed_settings` ON CONFLICT DO NOTHING).
* Architecture tests: no PySide6 in `app/core|services|analytics`; no `INSERT INTO`/`UPDATE `/
  `DELETE FROM` text in `app/ui` (upper-cased scan); no `INSERT OR REPLACE`; DeprecationWarning
  from `app.*` = error; quoted `"ADET"` only in quantity/errors/schema.
* `ScannerService` never consumes printable keys (only a burst Enter); `scanning_suspended`
  is not re-entrant; thresholds are constants; on Python 3.12/Windows `time.monotonic`
  ticks at ~15.6 ms.
* **No on-screen keypad/keyboard exists**: on the keyboardless AVAPOS a cashier cannot type a
  product name, price, PIN, amount or search text today.

## 2. Data-safety rules for the whole V1.2 run (critical)

The owner's **live V1.1 database** exists on this machine (`%LOCALAPPDATA%\TekelStok\tekelstok.db`)
and the deployed V1.1 exe is `dist\TekelStok\TekelStok.exe`. Therefore:

1. Every launch of the app or any tool during V1.2 work passes `--data-dir <scratch>` or sets
   `TEKEL_DATA_DIR` to a scratch folder. Screenshot, perf-dataset, benchmark and fixture tools
   **refuse to start** unless `TEKEL_DATA_DIR` is set and resolves outside
   `%LOCALAPPDATA%\TekelStok` (tested).
2. Never open, copy, inspect or migrate `%LOCALAPPDATA%\TekelStok` or the owner's
   `Documents\Tekel Stok Yedekleri`.
3. M0 archives the V1.1 build (`dist\TekelStok`, `TekelStok_tasinabilir.zip`) to gitignored
   `releases\TekelStok-1.1.0-rc1\`. `build_exe.py` gains `--out`; `verify_build.ps1` gains an
   exe-path parameter and **aborts (never kills)** if any TekelStok process is running.
   V1.2 builds go to `dist\TekelStok-1.2.0b1\`; `dist\TekelStok` stays V1.1 until the owner switches.
4. Migrations are **append-only once committed** (dev DBs may already be migrated).
5. No amend, rebase, `reset --hard`, force-push or tag move. `master` is never modified.
6. Any step that would open the real data directory or overwrite the deployed exe is a stop condition.

### 5.2 Kasa layout budget & overlay contract
Budget at 1000×600 (≈574 px usable):
* Kasa pages have **no PageHeader**. One toolbar row ≤ 64 px: compact `BarcodeInput` +
  56 px touch buttons **Ürün Ara, Beklet, Bekleyenler (n), Fiyat Gör, ⋯** (⋯ opens an in-page
  menu with Son Satışı Geri Al, Sepeti Boşalt, Hızlı Satış; `undo_button`/`clear_button`
  attributes preserved).
* Result strip height = measured `minimumSizeHint` of the longest SaleFlash/ResultBanner content
  (incl. "Para üstü" and the undo-gate text), or SaleFlash reduced to two lines.
* Cart list minimum 2 rows; **total + NAKİT + KART on one row** (buttons ≥ 88).
* Tests: `page.minimumSizeHint().height() <= stack.height()` at 1000×600 and 1092×614 for every
  Kasa page and overlay; every result-strip child fits; touch-target test over all Kasa buttons.

Overlay contract (Ürün Ara, Bekleyenler, Para Üstü):
1. Overlays are **asynchronous full-page children** with signals (`TenderPanel.confirmed(int)`,
   `.cancelled()`, `SearchPanel.product_chosen(int)`, …) driven by a state machine
   (`_overlay_state`) on `CartSalePage`. **No `QEventLoop.exec` in Kasa code** (architecture test;
   UI tests patch `QEventLoop.exec` to raise).
2. `_add_by_code` is the single entry for router scans **and** `BarcodeInput.submitted`; it refuses
   (blocked sound + notice inside the overlay) while Para Üstü or Bekleyenler is open; allowed while
   Ürün Ara is open, whose own feedback strip mirrors results/errors and the running total.
3. All cart/header/payment controls are disabled while an overlay is open.
4. `on_deactivated` closes any overlay with cancel semantics and releases its suspension token
   before `go_to` changes context; `_go_back` (Esc) first closes an open overlay; goto shortcuts
   cancel the tender first.
5. Overlays pass their own `on_blocked`; no F10 text anywhere on the cart page.

### 5.3 Touch input kit — `app/ui/widgets/touch_input.py`
* `TouchNumpad` (0–9, 00, virgül, ⌫, Temizle), `TouchKeyboard` (Turkish Q:
  `1234567890 / qwertyuıopğü / asdfghjklşi / zxcvbnmöç.` + **symbol layer** `- / ' , % & + ( ) * :`,
  Boşluk, ⌫, Büyük harf via `tr_upper`), keys ≥ 56 px (keyboard rows fit 736 px with 4 px gaps),
  `NoFocus`; `TouchDisplay` non-focusable value display.
* `ScanSafeLineEdit` (physical-keyboard fields, not `scannerExempt`): subscribes to
  `ScannerService.scanned`, snapshots text/cursor before any keypress after a gap > burst
  threshold, restores the snapshot when a scan arrives while focused. With `ekran_klavyesi=off`
  Kasa search uses it.
* Touch dialogs (PIN, product form host, amount/text dialogs): **no default/autoDefault buttons**,
  Return/Enter swallowed; submission only by tapping. The PIN dialog ignores physical digits that
  arrive at burst speed. Test: a 13-digit burst + Enter into an open PIN dialog records no attempt.
* Exact-text tests: "Puro/Sigarillo", "Coca-Cola", "Jack Daniel's", "İÇİ", i/İ/ı/I.

### 5.4 Manager PIN — `app/services/security_service.py` (Qt-free) + `app/ui/manager_guard.py`
* PIN 4–8 digits; trivial PINs rejected. `hashlib.scrypt(n=2**14, r=8, p=1, dklen=32)`,
  16-byte `secrets` salt, stored as `scrypt$16384$8$1$<salt>$<hash>` in `guvenlik_pin_hash`;
  `hmac.compare_digest`.
* Lockout 5 wrong → 1 min doubling to 30 min; counters persisted quietly; injectable monotonic clock.
* Unlock session ends on showing a Kasa page or 5 min inactivity.
* Recovery code `XXXX-XXXX-XXXX` shown once at setup (hashed). Last resort start flag
  `--yonetici-pin-sifirla`: GUI confirmation (type `SIFIRLA`), automatic `pin_sifirlama_oncesi_`
  backup, PIN cleared, audit row (actor `SYSTEM`), **persistent reset flag**: red banner on every
  Yönetim page, Ana Ekran tile and Sistem Durumu until a new PIN **with a new recovery code** is set
  **and** the owner acknowledges the notice; survives restart; shown in Geçmiş.
* Gate check in `go_to` **before** deactivating the current page, inside a suspension token; on
  refusal the previous nav button is re-checked and nothing changes (tested).
* `ProtectedAction`: `AYARLAR, GERI_YUKLE, TOPLU_FIYAT, ICE_AKTAR, URUN_PASIF,
  KATEGORI_PASIF_BIRLESTIR, GECMIS_SATIS_GERI_AL, FIS_GERI_AL, STOK_YENIDEN_HESAPLA, PIN_DEGISTIR`.
  Never: sales, Kasa undo of the latest sale (same business day), park/resume, price check,
  search, quick product add, navigation.
* Threat model (README + Güvenlik section): prevents accidental/casual shop-floor changes; not a
  defence against anyone with Windows/file access; backups contain the hash; restoring an old
  backup restores its PIN state. Every `guvenlik_*` key is redacted from support output.

| v6 (conditional) | M11 | Indexes proven by EXPLAIN + measurement only | none |

Engine (M1b), before any real migration ships:
1. `Database(path, pre_migration_backup_dir=None)`; inside `connect()`: open → pragmas →
   **newer-schema guard** (`schema_version > max(schema_mod.MIGRATIONS)` read at call time → close,
   raise) → if `0 < current < target`: **free-space precheck** ((db+wal)×1.2+50 MB) →
   **pre-migration backup** `guncelleme_oncesi_v{cur}_v{target}_<stamp>.db` (default dir
   `self.path.parent/'backups'`; fallback the manual backup dir; core never imports `config`) →
   migrate → FK ON. Covers `open_database`, `restore`, `_rollback`, self-test.
2. **All pending versions in ONE outer transaction**; FK check per version compared against a
   **pre-migration baseline** (pre-existing orphans become a Sistem Durumu advisory, not a block).
   Failure ⇒ file exactly at its starting version, connection closed, file unlocked, wrapped
   `VeritabaniHatasi` (cause chained).
3. If the backup is impossible ⇒ no migration; message names drive, required/free MB, backup
   path attempted, "Verileriniz değiştirilmedi; önceki sürümü kullanmaya devam edebilirsiniz";
   never mentions Ayarlar. `backup_to` deletes its `.tmp` on any failure.
4. `--surum-geri-donus <yedek.db>`: validated read-only (schema < current), live DB copied with the
   backup API to `geri_donus_oncesi_<stamp>.db`, atomic replace, sidecars removed, **not opened or
   migrated**, then "Şimdi V1.1'i başlatın" (archived exe from §2). README documents it.
5. Restoring an older backup migrates the restored copy; the user-selected source file is kept
   unchanged (tested via SHA-256).
6. `SCHEMA_VERSION` name-imports removed from `db.py`/`backup_service.py`; test asserts
   `SCHEMA_VERSION == MIGRATIONS[-1][0]`; migration tests generalised to `SCHEMA_VERSION+1`;
   `test_basarisiz_goc_semayi_yarim_birakmaz` expects `VeritabaniHatasi` with an `OperationalError`
   cause **plus** connection closed and file unlocked (stronger).
7. Self-test gains an upgrade check: build a v1 DB (`MIGRATIONS[:1]`) under a **non-ASCII** temp
   subfolder, open with latest code, assert pre-migration backup exists and passes `inspect()`,
   schema = latest, deep invariants clean — so the frozen build exercises the upgrade.

### 5.8 Cost semantics (D-06, D-20, user correction 2)
**Invariant:** `last_purchase_cost` / `last_purchase_at_utc` represent actual stock-in history
only. Purchase receipts are the normal source. The single pre-existing exception is kept and
documented: an `INITIAL_STOCK` (opening balance) entered **with an explicit cost** stamps as in
V1.1 (changing it would alter proven costing). V1.2 adds **no** other writer.

* `known_cost(product)`: `last_purchase_cost > 0` stamped by a non-estimated, non-bedelsiz inbound.
  Used everywhere for margin, Δ%, price review, margin-keeping suggestion, price-center "no cost"
  filter. `0`/NULL ⇒ "alış fiyatı bilinmiyor" (no margin, no Δ%, no suggestion).
* `apply_movement(..., cost_is_estimated=False)`; estimated **and** explicit-0 (bedelsiz) inbound
  never stamp `last_purchase_cost/at` and keep `last_avg_cost` derivation.
* `add_line(unit_cost=None)` = **no known cost** (only path to the estimate rule); Mal Kabul and
  Hızlı Stok UIs prefill `known_cost` and pass it **explicitly** (shown as "önceki alıştan").
  This is a deliberate API-semantics change logged with a strengthened test (two purchases at
  different costs ⇒ prefill = last cost, non-estimated). The "byte-identical" claim applies only
  to `apply_movement` callers.
* Estimated rule at commit (inside the transaction): pool avg → last avg → known last purchase → 0,
  flagged `cost_is_estimated=1`; never shifts the pool average beyond 1 kuruş (property tests).
* Receipt lines: merge key `(product_id, cost_is_estimated, unit_cost)` (estimated lines merge on
  `(product_id, 1)`); `set_line_cost` clears the flag and requires DRAFT; `changed_cost_lines`,
  "Önceki alış/Değişim %", price review and previous-purchase queries exclude estimated, contra and
  reversed lines; contra lines copy the flag.
* Commit captures `previous_unit_cost`, `previous_avg_cost`, `previous_purchase_at_utc`; reversal
  (LIFO line order, provable precondition) restores all three; estimated lines restore nothing.
* `quick_create`, `set_initial_stock`, clone path: no `or 0`; invalid cost text raises `GecersizFiyat`;
  stock without cost ⇒ estimated rule.
* **Reference cost** (`products.reference_cost`, `reference_cost_updated_at_utc`, v3): set by import
  cost column, Hızlı Ürün Ekle cost-without-stock, product edit. Label **"Referans alış (katalog)"**,
  never "Son alış". Used for catalogue info, pricing preview and price suggestions (labelled
  "referans maliyete göre, tahmini"). **Never** read by `cost_basis`, never stamps, never enters the
  pool or inventory value, never counts as trusted coverage. Tests prove each "never".
* Advisory changed to `COALESCE(last_purchase_cost,0)=0` (equal-or-stronger, logged).

### 5.9 Analytics attribution & cost tiers
* All period metrics attribute a reversal to the **original** sale's business date (raw queries:
  `entry_type='SALE' AND is_reversed=0`) — equivalent to netting (full single reversals only).
* Ödeme tab adds **"Bu dönemde yapılan iadeler"** by reversal business date and method
  (`entry_type='SALE_REVERSAL'`) for drawer reconciliation.
* I23 rewritten: attribute contra rows via `COALESCE(orig.business_date, s.business_date)`, compare
  both directions, include cost. New deep invariant **I34**: `daily_sales_rollup` (sale_count,
  total_amount, total_cost, item_count, cash_amount, card_amount) vs original-date sales.
* Cost tiers computed **from the ledger** at query time: a sale line is **"Güvenilir maliyet"** only
  if `is_estimated_cost=0`, `cost_total>0`, and no tainting inbound (`quantity_delta>fill_quantity`
  and (`is_estimated_cost=1` or `unit_cost` 0/NULL)) exists for its product between the last pool
  reset (`balance_after<=0`) before the sale movement and the sale movement; otherwise
  **"Tahmini maliyet"** (cost > 0) or **"Maliyeti bilinmiyor"** (cost 0). Headline gross profit only
  when trusted revenue ≥ 95 %; otherwise profit "kapsanan kısım için". Benchmarked in M11.

### 5.11 Backup architecture (J, user corrections 5–6)
* Snapshots always via the SQLite backup API through a **separate read-only connection**
  (never raw-copying the live file, no WAL/SHM dependence); stamp `last_backup_data_version` from
  the produced file; `Database.in_transaction` blocks backups; timer slots catch & log exceptions;
  error stamps guarded.
* `BackupInfo.kind` from exact filename regexes: OTOMATIK / GUNLUK / GUNCELLEME_ONCESI /
  ICE_AKTARMA_ONCESI / PIN_SIFIRLAMA_ONCESI / GERI_YUKLEME_ONCESI / GERI_DONUS_ONCESI / ELLE;
  `is_auto` means rolling `otomatik_` only (`test_saklama_siniri` unchanged).
* Managed names carry a per-install id (`schema_meta.install_id`):
  `otomatik_<id8>_YYYYmmdd_HHMMSS.db`, `gunluk_<id8>_<businessdate>.db`; a manifest
  `.tekelstok_yedekler.json` (name, size) lists created files. Cleanup deletes only manifest-listed
  regular files in the managed directory whose size matches, ordered by the **filename timestamp**
  (names > 1 day in the future ignored for ordering), never the newest N, never fewer than N,
  never a file created by the current process. Legacy V1.1 `otomatik_YYYYmmdd_HHMMSS.db` files in
  the default dir are honoured as ours.
* Retention: rolling = newest 10 generations; daily = newest N daily generations (N =
  `daily_backup_retention_days`, default 30, 7–365); pre-import capped at the last 10; pre-migration,
  pre-PIN-reset, pre-restore, pre-rollback never auto-deleted. Sistem Durumu shows total size + free space.
* `auto_backup_dir` configurable (writability probe); if missing/unwritable ⇒ fallback to default dir
  + recorded error; rejected if equal to/containing the data dir or equal to the manual dir.
* **Daily generation is opportunistic but hard to starve** (correction 6): today's daily backup is
  *required* when no `gunluk_*_<today>` exists and data changed since the last daily. Opportunities:
  (1) **startup** after open/migrate when safe; (2) **idle timer** every 5 min when no input/scan
  ≥ 60 s, no checkout busy, no overlay open; (3) **clean shutdown** if still required. Never
  duplicates a day's generation. Failures recorded (`last_backup_error*`), status-bar indicator,
  never block selling. Pre-migration/pre-import/pre-PIN-reset backups remain mandatory where stated.
* Free-space precheck with an accurate message; `inspect()` uses `Path.as_uri()`-style encoding.
* Restore safety: `Database.generation` increments on restore/rollback; carts carry their
  generation; `save_draft`/park refuse on mismatch and only touch `status='OPEN'` rows; after restore
  a `restarting` flag stops autosave, idle backups and close-time saves.

### 5.12 Clock seam (M1a)
`app/core/clock.py`: process-wide provider consulted **inside** `now_utc()`/`local_now()`
(`use_clock(...)` context manager + reset) so every existing name-import follows it; injectable
monotonic clock for PIN lockout, unlock session and idle backup. `tests/fakes.py` `SahteSaat`
installs it; the perf generator uses it to step simulated days.

## 8. Test strategy & conventions
* File-backed SQLite; UI offscreen via the shared harness; persistence via `reopen`; financial tests
  end with `check_invariants(deep=True) == []`.
* Red-proof for every defect: reverse-apply the fix in the working tree (`git stash push -- <files>`
  or `git apply -R`), run, restore — never commit a red state; evidence (test id + failing assertion)
  logged.
* Existing tests change only when a **requirement** changed and only to equal-or-stronger protection,
  each logged with the reason. Expected: migration tests → `SCHEMA_VERSION+1` and wrapped error;
  seed counts 20 → 34 (+ self-test); advisory predicate; `add_line(None)` prefill test strengthened;
  dashboard page → Analiz (attribute names kept).
* No wall-clock dependence (clock seam); sounds off; 10k+/wall-clock tests are `perf` with a small

## 12. Stop conditions
Stop and ask only for: irreversible user-data-loss risk; ambiguous destructive migration; materially
contradictory requirements; architecture-changing decision without a safer default; unknowable
hardware facts blocking work; a broken baseline; an invariant that would have to be abandoned; an
unsafe security decision; **any step that would open the real data directory or overwrite the
deployed exe**. Decided here (not stop conditions): openpyxl/CSV-only fallback, PIN storage &
recovery, theme approach, cost semantics incl. `reference_cost`, parked-cart price policy, template
policy, VAT labelling.
