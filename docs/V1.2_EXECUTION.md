1. `git status`. If dirty: compare the diff with the first unchecked sub-step below;
   either finish and commit it, or `git stash push -m "v1.2 resume <date>"` and log that.
   Never discard work.
2. Verify the environment versions above and that `.venv` exists.
3. Run the default suite: `.venv\Scripts\python.exe -m pytest tests -q -p no:cacheprovider`
   and compare the passed count with the latest entry.
4. Read the plan, the traceability matrix and this log; continue at the first unchecked
   sub-step in the status table. No other state is required.

## M12d-5 — Clipped button text (menu, side panel) and a native guard against it
* **Base commit:** `f5fa3af` (M12d-4).
* **Found by** inspecting the regenerated screenshot set, built from `f5fa3af`, zoomed:
  * `1366x768_yazi130/30_barkod_testi.png`: menu labels lost their descenders and cedillas
    ("Avarlar", "Fivat Yönetimi", "Gecmis", "Tedarikciler", "Kateqoriler").
  * At 100 % the "g" of "Kategoriler" was cut too. The defect was already visible in the M12b
    set and was missed there.
* **Cause (measured natively):**
  * The QSS `min-height` becomes the widget's explicit minimum. For a generic button that is
    `BUTTON_HEIGHT − 20 = 24` px of content; with the menu padding it is 48 px.
  * `qSmartMinSize` honours that minimum even for Fixed-policy buttons. When the menu doesn't
    fit, the `widgetResizable` scroll area sizes its content to the **minimum** (812 px
    instead of 854 at 100 % and 975 at 130 %).
  * Every menu button is therefore squeezed to 48 px: 24 px of content for a 27 px (100 %)
    or 35 px (130 %) text line.
  * The same happens to "Seçili değişikliği geri al" in Fiyat Yönetimi's scrollable side
    panel (every profile).
  * Kasa "⋯" at 130 %: a 52 px line in 44 px of content. The glyph is centred and not
    visibly cut, but it is flagged by the same rule.
  * Built in isolation, the buttons render correctly, so it only shows inside the real
    layout.
* **Fix (`app/ui/theme.py` `measured_rules`, the existing home for measured QSS heights):**
  * Generic `QPushButton`: minimum content = max(old value, measured base-font line).
  * `#navButton`: minimum = measured line.
  * `#navGroupHeader`: max(28, small-font line).
  * `#kasaMore`: max(touch value, its own font line).
  * Every minimum now equals the natural height, so no layout can squeeze text below its
    line, at any font scale.
* **Guard (`app/tools/ekran_goruntusu.py`):**
  * New `kirpilan_dugmeler()` flags a visible button whose `SE_PushButtonContents` height is
    shorter than its font's line height.
  * `tasmalar()` runs it on every page and once on the menu with all items shown; the saved
    open/closed state is restored afterwards.
  * The default suite's native test `test_yerel_cizimde_1000x600_tasma_yok` therefore now
    also guards clipping, and the gate runs it in all 7 profiles.
* **Red → green:**
  * Before the theme fix, native `--yalnizca-tasma`: **1000×600 taşma 19** (18 menu items +
    the Fiyat Yönetimi button, 27 > 24) and **130 % taşma 23** (35 > 24, plus "⋯" 52 > 44).
  * After: **all 7 profiles taşma 0**, including the Kasa vertical budget at 125 % and 130 %
    with the taller "⋯".
  * The scratch renders confirm whole labels at 130 %.
* **Tests:** 107 passed in the layout/theme files; **1021 passed, 5 deselected** (138 s).
